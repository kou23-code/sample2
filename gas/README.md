# お知らせ更新・問い合わせ受付用 GAS（Google Apps Script）の設定手順

スプレッドシートに書いたお知らせを、サイトのトップ（最新5件）とお知らせ一覧に表示するための仕組みです。
サイトは GAS の Webアプリ（URL の末尾が `/exec`）から JSON を取得し、取得できない場合は `js/data/news-data.js` の予備データを表示します。
同じ Webアプリで、問い合わせフォームの送信内容をシート「お問い合わせ」に保存し、担当者へ通知メールを送ります（6章）。

## 1. スプレッドシートと GAS を用意する（初回のみ）

1. Google ドライブで新しいスプレッドシートを作成する（共有は職員のみ。一般公開はしない）。
2. メニュー「拡張機能」→「Apps Script」を開く。
3. 最初からある `コード.gs` を削除し、次の6つのスクリプトファイルを作って内容を貼り付ける（お互いの関数を使うため、必ず6つともそろえる）。
   - `contact-validate`：このリポジトリの `js/lib/form-validate.js` の内容（サイトのフォームと同じ検証ルールを共用する）
   - `news-sheet`：このリポジトリの `gas/news-sheet.js` の内容
   - `news-admin`：このリポジトリの `gas/news-admin.js` の内容（管理画面用）
   - `contact-form`：このリポジトリの `gas/contact-form.js` の内容（問い合わせ用）
   - `contact-api`：このリポジトリの `gas/contact-api.js` の内容（問い合わせ用）
   - `news-api`：このリポジトリの `gas/news-api.js` の内容
4. **新しくシートを作る場合のみ**、上部の関数選択で `setupNewsSheet` を選んで「実行」する（初回は権限の承認が必要）。
   シート `news` に見出し・日付とカテゴリの入力規則・公開フラグのチェックボックスが作られる。
   すでに見出しを作って入力済みのシートでは実行しない（公開フラグを文字で入力している場合、G列がチェックボックスに変わるため）。

## 2. Webアプリとして公開する（初回のみ）

1. 右上の「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」を選ぶ。
2. 「次のユーザーとして実行」は **自分**、「アクセスできるユーザー」は **全員** にしてデプロイする。
3. 表示された URL（`https://script.google.com/macros/s/…/exec`）をコピーする。
4. サイトの `config.js`（`.gitignore` 対象。`config-sample.js` をコピーして作成）に設定する。

   ```js
   const SITE_CONFIG = {
     newsEndpoint: 'https://script.google.com/macros/s/…/exec',
   };
   ```

5. ブラウザで URL を直接開き、`{"updatedAt":"…","news":[…]}` が表示されることを確認する。

> コードを修正したときは「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」で更新すると、URL は変わらない。
> お知らせの追加・修正だけなら再デプロイは不要。

## 3. お知らせの書き方（職員向け）

| 列 | 見出し | 書き方 |
| --- | --- | --- |
| A | ID | お知らせを区別する番号など（例：`n-001`）。省略可 |
| B | 日付 | カレンダーから選ぶ。**今日より後の日付は、その日になるまで表示されない（予約公開）** |
| C | カテゴリ | お知らせ／イベント／教室情報／募集 から選ぶ |
| D | タイトル | 必須 |
| E | 本文 | お知らせ一覧に表示される（省略可） |
| F | 添付ファイルURL | 画像やPDFのURL（省略可）。Googleドライブのファイルは「リンクを知っている全員が閲覧可」にした共有リンクをそのまま貼る |
| G | 公開フラグ | チェックボックスの ✓、または「TRUE」「公開」「1」「○」「yes」の行だけがサイトに表示される（それ以外は下書き扱い） |
| H | 固定順位 | 数値を入れたお知らせは、日付に関係なく一覧の先頭に小さい順で並ぶ（1が一番上）。空欄なら日付の新しい順。固定をやめるときは空欄に戻す |

- 担当者名・電話番号・メールアドレスなどの個人情報はシートに書かない。
- 編集するとキャッシュが消え、次にサイトを開いたときに反映される（予約公開の切り替わりは最大5分ほど遅れる場合がある）。
- 日付やカテゴリに誤りがある行はサイトに表示されない（ブラウザの開発者ツールのコンソールに理由が出る）。
- 日付は日付型のセルのほか、文字の `2026/10/20`・`2026年10月20日` なども使える。

## 4. お知らせが表示されないとき

Webアプリの URL の末尾に `?debug=1` を付けて開くと、お知らせの中身は出さずに次の内容を表示する。

| 項目 | 意味 |
| --- | --- |
| `sheetFound` | シート `news` が見つかったか（`false` のときは `sheetNames` に実際のシート名が出る） |
| `headers` | 1行目の見出し（A〜G列の並びの確認用） |
| `rowCount` / `published` | 見出しを除いた行数／公開される行数 |
| `notPublished` と `notPublishedFlagSamples` | 公開フラグが公開と認識されなかった行数と、そのG列の値の例 |
| `invalidDate` と `invalidDateSamples` | 日付が読めなかった行数と、そのB列の値の例 |
| `future` | 日付が今日より後のため、まだ表示されない行数（予約公開） |

## 5. お知らせ管理画面（admin.html）を使う

職員がスプレッドシートを開かずに、サイトの `admin.html` からお知らせを追加できます（添付ファイルは Googleドライブに保存されます）。

### 5-1. 共通パスワードを登録する（初回のみ・コードには書かない）

1. GASエディタ左側の歯車「プロジェクトの設定」を開く。
2. 一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」を押す。
3. プロパティに `ADMIN_PASSWORD`、値に職員で共有するパスワードを入れて保存する。
   - 推測されにくい長めのもの（12文字以上・英数字記号の組み合わせ）にする。
   - パスワードを変えるときは、この値を書き換えるだけでよい（再デプロイは不要）。
   - パスワードは HTML・JavaScript・このリポジトリには絶対に書かない（公開サイトでは誰でも中身を見られるため）。

### 5-2. コードを更新して再デプロイする

1. 1章の6つのスクリプトファイルを、このリポジトリの最新の内容に置き換えて保存する（お互いの関数を使うため、必ず6つともそろえる）。
   シートの H1 セルに見出し「固定順位」を入れておく（見出しが無くても動くが、職員が分かりやすいように）。
2. 「デプロイ」→「デプロイを管理」→ 鉛筆アイコン → バージョン「新バージョン」→「デプロイ」。URL は変わらない。
3. ドライブへの保存を初めて使うため、権限の承認画面が出たら許可する（出ない場合は、関数選択で `doGet` を選んで一度「実行」すると承認画面が出る）。

### 5-3. 使い方

1. サイトの `admin.html` を開き、共通パスワードでログインする（メニューにはリンクしていないので、URL を直接開くかブックマークする）。
2. 日付・カテゴリ・タイトル・本文を入力し、必要なら添付ファイル（PDF・JPEG・PNG・GIF・WebP、10MBまで）を選んで「お知らせを追加する」を押す。
3. 追加したお知らせはすぐにサイトへ反映される。「サイトに公開する」のチェックを外すと下書きとして保存される。
4. 修正・削除は、今のところスプレッドシートを直接編集する。

### 5-4. 注意

- 添付ファイルは、マイドライブに自動で作られるフォルダ「お知らせ添付ファイル」に保存され、「リンクを知っている全員が閲覧可」になる。**個人情報を含むファイルは添付しない。**
  別のフォルダに保存したい場合は、スクリプト プロパティ `ADMIN_FOLDER_ID` にそのフォルダの ID を設定する。
- 会社の Google Workspace の設定で「リンクを知っている全員」への共有が禁止されている場合、追加時にエラーになる。そのときは Workspace の管理者に確認する。
- パスワードを15分以内に10回間違えると、15分間はログインできなくなる。
- 共通パスワードのため、誰が追加したかは記録されない。パスワードが漏れた疑いがあるときは、すぐに 5-1 の手順で変更する。

## 6. 問い合わせフォームの受付（シートへの保存と通知メール）

サイトの `contact.html` から送信された内容を、同じ Webアプリが受け取ります。

- スプレッドシートにシート **「お問い合わせ」** が自動で作られ（初回の送信時）、1件ごとに1行追記される。
- 担当者宛てに、全項目を記載した通知メールが届く。メールに **返信すると送信者に届く**（返信先を送信者のメールアドレスにしている）。
- サイトの `config.js` に `newsEndpoint`（2章の URL）を設定していれば、問い合わせも自動でその Webアプリへ送られる（`formEndpoint` の設定は不要）。
  `newsEndpoint` も `formEndpoint` も無い場合は、送信せずに完了画面だけを表示する（デモ）。

### 6-1. 通知先のメールアドレスを登録する（初回のみ・コードには書かない）

1. GASエディタの「プロジェクトの設定」→「スクリプト プロパティ」を開く。
2. プロパティに `CONTACT_NOTIFY_EMAIL`、値に通知を受け取るメールアドレスを入れて保存する（複数ならカンマ区切り）。
   - 登録しないと、仮置きのダミーアドレス `admin@example.com` 宛てになり、メールは届かない。
   - メールアドレスは HTML・JavaScript・このリポジトリには書かない。

### 6-2. コードを更新して再デプロイする

1. 1章の6つのスクリプトファイルをそろえて保存し、5-2 と同じ手順で「新バージョン」としてデプロイする（URL は変わらない）。
2. メールの送信を初めて使うため、権限の承認が必要。関数選択で `doGet` を選んで一度「実行」し、承認画面で許可する
   （「ユーザーとしてメールを送信」の権限が追加で表示される）。
3. サイトの `contact.html` からテスト送信し、シート「お問い合わせ」に行が追加され、通知メールが届くことを確認する。

### 6-3. シート「お問い合わせ」の列

| 列 | 見出し | 内容 |
| --- | --- | --- |
| A | 受付日時 | `2026-10-23 10:00:00` の形（GAS のタイムゾーン。「プロジェクトの設定」で「(GMT+09:00) 日本標準時」にしておく） |
| B | 種別 | 体験申込／一般的なお問い合わせ |
| C〜I | 希望教室・希望日・保護者名・参加者のお名前・学校名・学年・年齢 | 体験申込のときだけ入る |
| J | お名前 | 一般的なお問い合わせのときだけ入る |
| K〜M | メールアドレス・電話番号・お問い合わせ内容 | 両方で入る |
| N | 対応状況 | 「未対応」で追加される。対応したら職員が「対応済」などに書き換える |

- シートは書式なしテキストで作るため、電話番号の先頭の 0 も消えない。
- 列の並びは変えない（変えると新しい行が別の列に書き込まれる）。右側に職員用のメモ列を足すのはかまわない。

### 6-4. 注意

- **このシートには個人情報（氏名・連絡先・学校名など）が保存される。** スプレッドシートの共有は担当職員だけにし、「リンクを知っている全員」には絶対に共有しない。不要になった行は定期的に削除する。
- Webアプリは誰でも送信できるため、いたずらの大量送信に備えて **10分間に20件** を超える送信は受け付けない（サイトには「お電話で…」と表示される）。
- 個人の Google アカウントでは、メールの送信は **1日100通** までが上限。上限を超えた場合もシートへの保存は行われる（通知メールだけが届かない）。
- 送信内容はサイトと同じルールで GAS でも再チェックし、誤りがあれば保存もメールもしない。希望日は端末との時差を考え、GAS 側では「明日以降」を受け付ける（サイトでは明後日以降しか選べない）。
- 受付で問題が起きたときは、GASエディタ左側の「実行数」でエラーの内容を確認できる。
